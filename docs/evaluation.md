# Veridex v2 evaluation

Measured 2026-10-22 on the deployed configuration: 35 fixed questions scored with RAGAS,
a provider comparison on the 20 corpus questions, and latency on the Cloud Run service
(warm and cold). Headline numbers for the routed system:

| Faithfulness | Answer relevancy | Context precision | Context recall | Mean cost / query | Warm median: first event / first token / total |
| --- | --- | --- | --- | --- | --- |
| 0.90 | 0.79 | 0.96 | 1.00 | $0.024 | 2.2 s / 12.0 s / 21.2 s |

A cold start (zero running instances) delays the first byte to 44–54 s.

## Method

| Item | Choice |
| --- | --- |
| Questions | [`eval/questions_v3.json`](../eval/questions_v3.json): 20 corpus RAG, 5 comparison / multi-step, 3 summary, 4 data (SQL), 3 web. References for all but web were written from Corpus v3 text and the paper catalog; web questions have no fixed reference because current information changes |
| System runs | in-process, real MCP servers and real providers, one fresh session per question (`scripts/evaluate.py answers`) |
| Contexts given to RAGAS | full text of every source retrieved in the turn: corpus chunks, read pages, web results, SQL result rows |
| RAGAS | 0.4.3; `Faithfulness`, `ResponseRelevancy` (answer relevancy), `LLMContextPrecisionWithReference`, `LLMContextRecall`; reference-free metrics only for web questions |
| Judge | `gpt-6.1-sol` (default temperature, which GPT-6 requires) with `text-embedding-3-small` for answer relevancy |
| Latency | client side over SSE against <https://veridex-v2-596419356898.us-west1.run.app>, with the server's own retrieval and LLM timing from the `done` event (`scripts/evaluate.py latency`) |
| Cost | token usage reported by each provider, priced in `veridex.llm.usage` (Gemini 3.8 Flash $0.75 / $3.75 per 1M from Google's pricing page; GPT-6.1 Sol $2 / $10 per 1M from OpenAI's pricing page, Standard tier, short context) |

Raw results are in [`eval/results/`](../eval/results/) (files ending in `_before` are the
first configuration, see [the change below](#change-gemini-reasoning-budgets)); the
tables are generated by `veridex.evaluation.report`.

## RAGAS (routed system)

| Category | n | Faithfulness | Answer relevancy | Context precision | Context recall |
|---|---|---|---|---|---|
| Corpus RAG | 20 | 0.91 | 0.81 | 0.95 | 1.00 |
| Comparison / multi-step | 5 | 0.98 | 0.80 | 0.96 | 1.00 |
| Summary | 3 | 0.86 | 0.64 | 0.94 | 1.00 |
| Data (SQL) | 4 | 0.96 | 0.89 | 1.00 | 1.00 |
| Web | 3 | 0.63 | 0.65 | – | – |
| **All** | 35 | **0.90** | **0.79** | **0.96** | **1.00** |

- **Corpus and comparison answers are grounded:** faithfulness 0.91 on single-paper
  questions and 0.98 on comparisons (four of five route research to OpenAI). Context recall is 1.00
  because agents retrieve several focused queries per question (about 14 passages on
  average), so every reference fact was present; this is generous, not a sign of a
  perfect retriever.
- **Summaries score lower on answer relevancy (0.64)** because a structured summary
  (gist, problem, method, results, limitations) answers more than the one-line question.
- **Web answers are the weakest (faithfulness 0.63):** Tavily search returns short
  snippets, and answers about recent work partly rely on pages the agent only saw as
  snippets. These answers cite their URLs, but the citations cover less of the text.
- A first scoring pass gave the Data questions 0.00 because SQL rows were not passed to
  RAGAS as contexts; the harness now includes them (and full web extracts).

Both providers do real work: 8 of 35 turns used OpenAI (four comparison questions, two

service one supervisor call fell back from Gemini to OpenAI on 2026-10-22 and was shown
as a fallback.

## Provider comparison

The 20 corpus questions with every agent forced onto one provider
(`ROUTER_FORCE_PROVIDER`), scored by the same judge. **Measured with the first
configuration** (Gemini default reasoning, before the change below); the routed row is
the same configuration, so the three rows are comparable with each other.

| Provider (all agents) | Faithfulness | Answer relevancy | Context precision | Context recall | Mean cost / query | Median total (s) | Output tokens / query |
|---|---|---|---|---|---|---|---|
| OpenAI `gpt-6.1-sol` | 0.97 | 0.85 | 0.94 | 1.00 | $0.0444 | 28.7 | 1,043 |
| Gemini `gemini-3.8-flash` | 0.90 | 0.82 | 0.93 | 1.00 | $0.0315 | 32.6 | 2,701 |
| Routed (hybrid) | 0.93 | 0.82 | 0.94 | 1.00 | $0.0329 | 32.8 | 2,544 |

- **Quality:** OpenAI is the most faithful (0.97 vs 0.90); retrieval quality is the same
  because both use the same tools and index.
- **Cost:** Gemini's token price is 2.7x lower, but with default reasoning it wrote 2.6x
  more output tokens (thinking tokens are billed as output), so it was only 29% cheaper
  per query, and slower (32.6 s vs 28.7 s).
- **What this changed:** the finding led to the per-rule reasoning budgets below, which
  make the Gemini routes cheap and fast as intended while synthesis-heavy questions keep
  going to OpenAI.

## Change: Gemini reasoning budgets

Gemini 3.8 Flash reasons by default, spending hundreds of billed output tokens and a few
seconds even on a one-word routing decision. The router now sets a reasoning
(`thinking_budget`) per rule: 0 for `classify`, 512 for `structured_lookup`, 1024 for
`single_lookup`; long-context summaries and all OpenAI calls are unchanged. The budget
is part of each routing decision and is shown in the UI. Same 30 questions, before and
after:

| Measure (same 30 questions) | Before | After |
|---|---|---|
| Median first token (in-process) | 19.1 s | 9.7 s |
| Median total (in-process) | 32.4 s | 20.0 s |
| Mean cost / query | $0.0313 | $0.0201 |
| Gemini output tokens / query | 2,293 | 1,238 |
| Faithfulness | 0.90 | 0.89 |
| Answer relevancy | 0.79 | 0.79 |
| Context precision | 0.96 | 0.96 |
| Deployed warm median: first event / first token / total (10 questions) | 3.3 / 21.6 / 36.6 s | 2.0 / 10.6 / 19.8 s |

Time to first token halved and cost fell by a third with no measurable quality change
(faithfulness −0.01 is within run-to-run variation for 30 questions).

Warm: the service had served requests within the previous minutes. Cold: measured only
after the Cloud Monitoring `instance_count` metric showed zero instances, and a
"Starting new instance" log entry confirmed the request started a new instance.

Earlier cold samples with the first configuration: rag-01 first event 44.8 s, total
86.6 s; dat-01 first event 43.8 s, total 53.5 s.

**Representative warm latency (all 12):** first event (the supervisor's routing
decision) after a median 2.2 s, first answer token after 12.0 s, complete answer after
21.2 s. Data questions finish in 10–16 s; most corpus questions in 14–21 s; comparisons
and summaries in 35–45 s; the recency web question takes about 70 s.

**Cold start:** 44–54 s pass before the first byte versus about 2 s warm. Cloud Run
starts a new instance and the app connects to all four MCP servers (three local child
processes and Tavily Remote MCP) before it serves. Locally the same container is ready in
about 7 s, so most of the delay is pulling and starting the image on a new instance. The
request does not fail; it waits.

**With one warm instance (`--min-instances=1`, enabled 2026-10-24 for grading):** after 21
minutes without traffic, rag-01 returned its first event after 2.5 s, first token after
11.1 s and the full answer after 18.6 s; no new instance was started, so the cold start
is gone at about $0.86 per day.

**Why the first token still takes about 10 s:** the answer streams from the worker's
final model call, which comes after its tool rounds; LLM time is 80–97% of each request
and retrieval about 1 s. The routing decision and every orchestration step stream
immediately, so the UI shows progress from about 2 s.

## Limitations and next steps

- The question set is small (35) and written by the developer; the web questions have no
  references. RAGAS uses one judge model, which is also one of the two generators and
  may favour its own answers.
- The provider comparison table predates the reasoning-budget change (see above).
- GPT-6.1 Sol is priced at the Standard short-context rate ($2 / $10); OpenAI's
  long-context rate is $4 / $15, so any long-context call is underestimated here.
- Latency: streaming a worker's draft earlier would shorten the first
  token further.

## Reproducing

```bash
uv run python scripts/evaluate.py answers --mode routed
uv run python scripts/evaluate.py answers --mode openai --categories rag
uv run python scripts/evaluate.py answers --mode gemini --categories rag
uv run python scripts/evaluate.py ragas --mode routed
uv run python scripts/evaluate.py ragas --mode openai
uv run python scripts/evaluate.py ragas --mode gemini
uv run python scripts/evaluate.py latency --url https://veridex-v2-596419356898.us-west1.run.app --label warm --ids rag-01 rag-04 rag-09 rag-12 rag-16 dat-01 dat-03 sum-01 web-01 web-02 cmp-01 cmp-05
uv run python -c "from veridex.evaluation.report import write_all; print(write_all())"
```

# Veridex v2 evaluation

Measured 2026-10-22 on the code in this branch: 30 fixed questions scored with RAGAS,
a provider comparison on the 20 corpus questions, and latency on the deployed Cloud Run
service (warm and cold). Headline numbers for the routed system:

| Faithfulness | Answer relevancy | Context precision | Context recall | Mean cost / query | Warm median: first event / first token / total |
| --- | --- | --- | --- | --- | --- |
| 0.90 | 0.79 | 0.95 | 1.00 | $0.031 | 3.3 s / 21.6 s / 36.6 s |

A cold start (zero running instances) adds about 40 s before the first byte.

## Method

| Item | Choice |
| --- | --- |
| Questions | [`eval/questions_v3.json`](../eval/questions_v3.json): 20 corpus RAG, 3 summary, 4 data (SQL), 3 web. References for RAG, summary and data were written from Corpus v3 text and the paper catalog; web questions have no fixed reference because current information changes |
| System runs | in-process, real MCP servers and real providers, one fresh session per question (`scripts/evaluate.py answers`) |
| Contexts given to RAGAS | full text of every source retrieved in the turn: corpus chunks, read pages, web results, SQL result rows |
| RAGAS | 0.4.3; `Faithfulness`, `ResponseRelevancy` (answer relevancy), `LLMContextPrecisionWithReference`, `LLMContextRecall`; reference-free metrics only for web questions |
| Judge | `gpt-6.1-sol` (default temperature, which GPT-6 requires) with `text-embedding-3-small` for answer relevancy |
| Latency | client side over SSE against <https://veridex-v2-596419356898.us-west1.run.app>, with the server's own retrieval and LLM timing from the `done` event (`scripts/evaluate.py latency`) |
| Cost | token usage reported by each provider, priced in `veridex.llm.usage` (Gemini 3.8 Flash $0.75 / $3.75 per 1M from Google's pricing page; GPT-6.1 Sol $2 / $10 per 1M from third-party price lists) |

Raw results are in [`eval/results/`](../eval/results/); the tables below are generated by
`veridex.evaluation.report`.

## RAGAS (routed system)

| Category | n | Faithfulness | Answer relevancy | Context precision | Context recall |
|---|---|---|---|---|---|
| Corpus RAG | 20 | 0.93 | 0.82 | 0.94 | 1.00 |
| Summary | 3 | 0.89 | 0.66 | 0.97 | 1.00 |
| Data (SQL) | 4 | 0.94 | 0.80 | 1.00 | 1.00 |
| Web | 3 | 0.62 | 0.73 | – | – |
| **All** | 30 | **0.90** | **0.79** | **0.95** | **1.00** |

- **Corpus answers are grounded:** faithfulness 0.93 and context precision 0.94 on the
  20 RAG questions. Context recall is 1.00 because agents retrieve several focused
  queries per question (about 13 passages on average), so every reference fact was
  present; this is generous, not a sign of a perfect retriever.
- **Summaries score lower on answer relevancy (0.66)** because a structured summary
  (gist, problem, method, results, limitations) answers more than the one-line question.
- **Web answers are the weakest (faithfulness 0.62):** Tavily search returns short
  snippets, and answers about recent benchmarks partly rely on pages the agent only saw
  as snippets. These answers cite their URLs, but the citations cover less of the text.
- A first scoring pass gave the Data questions 0.00 because SQL rows were not passed to
  RAGAS as contexts; the harness now includes them (and full web extracts), and those
  seven questions were re-run and re-scored.

## Routing decisions

Every decision in the routed run (30 questions):

| Agent | Rule | Provider | Decisions | Fallbacks |
|---|---|---|---|---|
| supervisor | `classify` | Gemini | 60 | 0 |
| research | `single_lookup` | Gemini | 20 | 0 |
| research | `multi_step_synthesis` | OpenAI | 3 | 0 |
| summary | `long_context` | Gemini | 3 | 0 |
| data | `structured_lookup` | Gemini | 4 | 0 |

Both providers are exercised: OpenAI handled the web and recency questions (178 Gemini
calls and 10 OpenAI calls in total). The question set is mostly single-paper lookups, so
the cost rules dominate; comparison questions (for example "How does it compare with
Reflexion?") and `sql_repair` route to OpenAI in live use, and one supervisor call fell
back from Gemini to OpenAI on the deployed service on 2026-10-22.

## Cost per query

| Run | Questions | Mean cost / query | Total | Median total (s) | Median first token (s) | Median retrieval (s) | Median LLM (s) |
|---|---|---|---|---|---|---|---|
| routed | 30 | $0.0313 | $0.94 | 32.4 | 19.1 | 1.3 | 30.2 |
| all OpenAI | 20 | $0.0444 | $0.89 | 28.7 | 16.0 | 1.0 | 27.8 |
| all Gemini | 20 | $0.0315 | $0.63 | 32.6 | 18.4 | 1.1 | 31.3 |

By category in the routed run: data $0.007, corpus RAG $0.033, summary $0.035, web
$0.049 per query. Per query the routed system uses about 23,000 Gemini input tokens and
a few OpenAI calls; embeddings for retrieval queries cost under $0.0001. Building the
index cost $0.012 once. Grading with RAGAS cost about $0.12 per question, far more than
answering it. Tavily calls used the free plan's credits.

## Provider comparison

The same 20 corpus questions with every agent forced onto one provider
(`ROUTER_FORCE_PROVIDER`), scored by the same judge:

| Provider (all agents) | Faithfulness | Answer relevancy | Context precision | Context recall | Mean cost / query | Median total (s) | Output tokens / query |
|---|---|---|---|---|---|---|---|
| OpenAI `gpt-6.1-sol` | 0.97 | 0.85 | 0.94 | 1.00 | $0.0444 | 28.7 | 1,043 |
| Gemini `gemini-3.8-flash` | 0.90 | 0.82 | 0.93 | 1.00 | $0.0315 | 32.6 | 2,701 |
| Routed (hybrid) | 0.93 | 0.82 | 0.94 | 1.00 | $0.0329 | 32.8 | 2,544 |

- **Quality:** OpenAI is the most faithful (0.97 vs 0.90); retrieval quality is the same
  because both use the same tools and index.
- **Cost:** Gemini's token price is 2.7x lower, but it writes 2.6x more output tokens
  (thinking tokens are billed as output), so its cost per query is only 29% lower.
- **Latency:** OpenAI was slightly faster (median 28.7 s vs 32.6 s) despite the larger
  model, again because of Gemini's longer reasoning.
- **Routing trade-off:** the hybrid keeps Gemini's cost (within $0.002 per query) and
  recovers part of OpenAI's faithfulness by sending synthesis-heavy questions to OpenAI.
  The measured gap suggests that sending every research call to OpenAI would buy +0.04
  faithfulness for about +$0.011 per query; the cost rule for `single_lookup` is kept
  because it is the cheaper path, and this is the first rule to revisit.

## Latency on Cloud Run

Warm: the service had served requests within the previous minutes. Cold: measured only
after the Cloud Monitoring `instance_count` metric showed zero instances, and a
"Starting new instance" log entry confirmed the request started a new instance.

|---|---|---|---|---|---|---|---|---|
| warm | rag-01 | rag | 6.0 | 25.3 | 41.5 | 7.2 | 33.8 | $0.0370 |
| warm | rag-04 | rag | 3.6 | 24.5 | 40.1 | 1.1 | 38.7 | $0.0355 |
| warm | rag-09 | rag | 3.4 | 22.7 | 37.1 | 1.1 | 35.8 | $0.0318 |
| warm | rag-12 | rag | 2.7 | 20.4 | 36.1 | 1.3 | 34.6 | $0.0321 |
| warm | rag-16 | rag | 3.7 | 16.0 | 22.5 | 0.9 | 21.3 | $0.0193 |
| warm | dat-01 | data | 2.6 | 7.6 | 11.0 | 0.1 | 10.7 | $0.0052 |
| warm | dat-03 | data | 2.8 | 10.2 | 14.5 | 0.1 | 14.4 | $0.0076 |
| warm | sum-01 | summary | 3.2 | 17.5 | 34.5 | 3.2 | 31.1 | $0.0399 |
| warm | web-01 | web | 3.2 | 57.3 | 77.3 | 15.2 | 62.0 | $0.0668 |
| warm | web-02 | web | 4.8 | 40.0 | 58.8 | 4.1 | 54.5 | $0.0270 |
| cold | rag-01 | rag | 44.8 | 69.0 | 86.6 | 6.7 | 40.0 | $0.0303 |
| cold | dat-01 | data | 43.8 | 50.0 | 53.5 | 0.1 | 14.8 | $0.0048 |

**Representative warm latency:** first event (the supervisor's routing decision) after a
median 3.3 s, first answer token after 21.6 s, complete answer after 36.6 s. Data
questions finish in 11–15 s; web questions take 59–77 s.

**Cold start:** about 40 s is added before the first byte (44.8 s and 43.8 s vs 3–6 s
warm): Cloud Run starts the container, and the app connects to all four MCP servers
(three local child processes and Tavily Remote MCP) before it serves. Locally the same
container is ready in about 7 s, so most of the delay is pulling and starting the image
on a new instance. The request does not fail; it waits.

**Why the first token is late:** the answer streams from the worker's final model call,
which comes after its tool rounds; LLM time is 80–97% of each request and retrieval is
about 1 s. The routing decision and every orchestration step stream immediately, so the
UI shows progress from about 3 s.

## Limitations and next steps

- The question set is small (30) and written by the developer; the web questions have no
  references. RAGAS uses one judge model, which is also one of the two generators.
- Prices for GPT-6.1 Sol come from third-party lists; confirm on the OpenAI dashboard.
- Latency: setting `--min-instances=1` during grading would remove the cold start (at the
  cost of an always-on instance); streaming the worker's draft earlier or parallelizing
  supervisor and retrieval would shorten time to first token.

## Reproducing

```bash
uv run python scripts/evaluate.py answers --mode routed
uv run python scripts/evaluate.py answers --mode openai --categories rag
uv run python scripts/evaluate.py answers --mode gemini --categories rag
uv run python scripts/evaluate.py ragas --mode routed
uv run python scripts/evaluate.py ragas --mode openai
uv run python scripts/evaluate.py ragas --mode gemini
uv run python scripts/evaluate.py latency --url https://veridex-v2-596419356898.us-west1.run.app --label warm --ids rag-01 rag-04 rag-09 rag-12 rag-16 dat-01 dat-03 sum-01 web-01 web-02
uv run python -c "from veridex.evaluation.report import write_all; print(write_all())"
```

The full run cost about $12 (OpenAI about $10 for answers and the RAGAS judge, Gemini
about $2).
